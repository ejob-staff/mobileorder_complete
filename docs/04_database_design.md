# DB設計
この資料は、モバイルオーダーアプリのDB設計として<br>
DBテーブル概要と初期データを整理したものです。

## 10. DBテーブル概要
app_user:
- ユーザー情報を管理する
- ユーザー名、パスワード、表示名、権限、利用状態を持つ

user_management_code:
- ユーザー管理番号を管理する
- 管理番号、使用済みかどうか、使用ユーザー名、作成日時、使用日時を持つ

product:
- 商品情報を管理する
- 商品名、説明、カテゴリ、値段、在庫数、公開状態、表示用アクセントを持つ

mobile_order:
- 注文情報を管理する
- 注文番号、ユーザー名、注文日時、受け取り日時、合計金額、ステータス、キャンセル理由、受取完了日時を持つ

order_item:
- 注文に含まれる商品情報を管理する
- 商品ID、商品名、注文時の値段、数量を持つ

product_review:
- 商品評価を管理する
- 注文番号、商品ID、商品名、ユーザー名、評価、感想、登録日時を持つ

## 11. 初期データ
初期ユーザー:
- 一般ユーザー: user / password
- 一般ユーザー: user2 / password
- 一般ユーザー: user3 / password
- 一般ユーザー: user4 / password
- 管理者ユーザー: admin / password
- 管理者ユーザー: admin2 / password

初期ユーザー管理番号:
- 一般ユーザー用: USER-CODE-英数字12桁
- 管理者用: ADMIN-CODE-英数字12桁

初期商品:
- 季節限定
- ケーキ
- 焼き菓子
- タピオカ
- ドリンク
- プレミアム

例:
- いちごタピオカミルクティ
- 濃厚タピオカミルクティ
- 黒糖タピオカラテ
- 抹茶タピオカミルク
- マンゴータピオカヨーグルト
- チョコタピオカミルク
- ピーチタピオカティー

初期注文:
- いちごタピオカミルクティの注文数を多めに登録する
- 注文分析、人気順、評価表示が確認しやすいようにサンプル注文を登録する

初期評価:
- いちごタピオカミルクティは高評価が多くなるように登録する
- 商品選択画面の評価表示、管理者の注文評価確認画面、注文分析画面で確認できる

注意:
- DataInitializerは対象テーブルにデータが存在しない場合に初期データを登録する
- 既にDBにデータが入っている場合は新しく追加した初期データは自動追加されない場合がある
- 初期データを入れ直したい場合はDBデータをリセットしてからアプリケーションを起動する
