## DB設計
### DB名
`mobileorder`

### テーブル一覧
`app_user`<br>
　テーブル名: ユーザー情報<br>
　用途: ユーザー情報を管理する<br>
　カラム: ユーザー名、パスワード、表示名、権限、利用状態<br>

`user_management_code`<br>
　テーブル名: ユーザー管理番号<br>
　用途: ユーザー管理番号を管理する<br>
　カラム: 管理番号、使用済みフラグ、使用ユーザー名、作成日時、使用日時<br>

`product`<br>
　テーブル名: 商品情報<br>
　用途: 商品情報を管理する<br>
　カラム: 商品名、説明、カテゴリ、値段、在庫数、公開状態、表示用アクセント<br>

`mobile_order`<br>
　テーブル名: 注文情報<br>
　用途: 注文情報を管理する<br>
　カラム: 注文番号、ユーザー名、注文日時、受け取り日時、合計金額、ステータス、キャンセル理由、受取完了日時<br>

`order_item`<br>
　テーブル名: 注文明細<br>
　用途: 注文に含まれる商品情報を管理する<br>
　カラム: 商品ID、商品名、注文時の値段、数量を持つ<br>

`product_review`<br>
　テーブル名: 商品評価<br>
　用途: 商品評価を管理する<br>
　カラム: 注文番号、商品ID、商品名、ユーザー名、評価、感想、登録日時<br>

### 初期データ登録

`初期ユーザー`<br>
　一般ユーザー: user / password<br>
　一般ユーザー: user2 / password<br>
　一般ユーザー: user3 / password<br>
　一般ユーザー: user4 / password<br>
　管理者ユーザー: admin / password<br>
　管理者ユーザー: admin2 / password<br>

`初期ユーザー管理番号`<br>
　各ユーザーに使用済みの管理番号を登録する<br>
　一般ユーザー用: 「USER-CODE-英数字12桁」<br>
　管理者ユーザー用: 「ADMIN-CODE-英数字12桁」<br>
　管理番号はアプリケーション起動時にランダム生成する

`初期商品`<br>
　19件の商品を登録する<br>
　カテゴリは以下の6種類<br>

`季節限定`<br>
　ケーキ<br>
　焼き菓子<br>
　タピオカ<br>
　ドリンク<br>
　プレミアム<br>

`商品例`<br>
　いちごタピオカミルクティ<br>
　濃厚タピオカミルクティ<br>
　黒糖タピオカラテ<br>
　抹茶タピオカミルク<br>
　マンゴータピオカヨーグルト<br>
　チョコタピオカミルク<br>
　ピーチタピオカティー<br>
　濃厚ショコラケーキ<br>
　ロイヤルハニークッキー<br>
　キャラメルバニラワッフル<br>

`初期注文`<br>
　一般ユーザーと管理者ユーザーにサンプル注文を登録する<br>
　いちごタピオカミルクティの注文を36件登録する<br>
　濃厚タピオカミルクティと焼き菓子を含む注文を18件登録する<br>
　季節限定商品とドリンクを含む注文を6件登録する<br>
　プレミアム商品の注文を6件登録する<br>
　調理中と未対応の注文を1件ずつ登録する<br>
　注文番号は「MOBILE-CODE-数字6桁」の形式でランダム生成する<br>

`初期評価`<br>
　いちごタピオカミルクティにスター評価が5の注文を30件登録する<br>
　濃厚タピオカミルクティにスター評価が4または5の注文を14件登録する<br>
　一部の焼き菓子とケーキにもスター評価を登録する<br>
　商品選択画面、注文評価確認画面、注文分析画面で確認できる<br>

`DataInitializer`<br>
　対象テーブルにデータが存在しない場合に初期データを登録する<br>
　既にDBにデータが存在する場合は追加した初期データが自動登録されないことがある<br>
　初期データを入れ直す場合はDBデータをリセットしてからアプリケーションを起動する<br>
